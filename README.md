# raburd — ตอบตรงสิ่งที่ต้องการ อ้างอิงจากการใช้งานจริง

เว็บถาม-ตอบที่ไม่ได้ตอบแค่ตามตัวอักษรของคำถาม แต่ **อ่านก่อนว่าผู้ถามต้องการอะไรจริง ๆ** โดยเทียบกับคำถามจริงที่เคยถามมาแล้ว
(ประวัติการใช้ Claude ของผู้ใช้ + คำถามที่ถามในเว็บนี้) แล้วจึงตอบให้ตรงรูปแบบนั้น — ทุกคำตอบแสดงเหตุผลและเคสที่ใช้อ้างอิง

## ทำไมต้อง "อ่านความต้องการ" ก่อน

จากประวัติการใช้ Claude จริงของผู้ใช้ (ก.ย. 2026) คำถามสั้น ๆ มักมีความต้องการที่ไม่ได้พิมพ์ออกมา:

| คำถามจริง | สิ่งที่ต้องการจริง (ดูจากสิ่งที่เกิดขึ้นหลังได้คำตอบ) |
|---|---|
| “เขียน train มาให้ใช้ในเครื่อง” | ไฟล์ที่รันจบได้ทันที — แต่ได้เวอร์ชันซับซ้อน แล้ว ~6 ชม. ต่อมาต้องขอใหม่ว่า “แบบง่าย ๆ ไม่ advance” |
| “บอกมาสั้นๆ ว่า … มี cell อะไรบ้าง” | รายการสั้น ๆ อย่างเดียว ไม่ต้องมีเรื่องอื่นปน |
| “พวก signal ต่างๆ มันใช้ได้ไหม” | ตัวเลขยืนยัน เทียบ baseline ไม่ใช่ความเห็น |
| (แนบไฟล์ handoff อย่างเดียว) | ทำงานต่อทันที — ถูกถามกลับแล้วไม่ตอบ แต่สั่งให้ทำไฟล์แทน |
| push ไม่ได้ 403 (เกิดซ้ำ 5 ครั้ง) | รู้ว่าใครต้องแก้อะไร + ไม่ให้งานหาย |

ข้อมูลเหล่านี้ถูกสรุปเป็น **เคส** (คำถาม / ความต้องการจริง / คำตอบที่ได้ / ผลลัพธ์ / บทเรียน) ใน
[`public/data/knowledge/claude-history.json`](public/data/knowledge/claude-history.json) และสกัดเป็น
**ประเภทความต้องการ 8 แบบ** พร้อมคำสัญญาณและวิธีตอบใน [`public/data/needs.json`](public/data/needs.json)
และโปรไฟล์ผู้ใช้ใน [`public/data/profile.json`](public/data/profile.json) (ตัดชื่อบุคคล/อีเมลออกแล้ว)

## ทำงานอย่างไร

```
คำถาม ─┬─► ค้นเคสจริงที่คล้ายที่สุด  (TF-IDF ตัดคำไทยด้วย Intl.Segmenter + n-gram ตัวอักษร,
       │                            วัดจากวิธีถามที่ใกล้ที่สุดของแต่ละเคส)
       ├─► อ่านความต้องการ          (คำสัญญาณในคำถาม + ความต้องการจริงของเคสที่คล้าย + ผลโหวตย้อนหลัง)
       ├─► ตอบ                      Claude (claude-opus-5-5) ได้ความต้องการ + เคสอ้างอิง + วิธีตอบ
       │                            ไม่มี API key → ตอบจากเคสจริง และไม่เดาเมื่อไม่มีเคสที่ใกล้พอ
       └─► เรียนรู้                  ปุ่ม “ตรง / ไม่ตรง + จริง ๆ ต้องการอะไร” → บันทึกเป็นข้อมูลการใช้งานจริง
                                    คำถามที่ยืนยันแล้วกลายเป็นเคสอ้างอิงของคำถามถัดไป
```

- คำตอบที่ Claude เขียนแล้วได้ 👍 ถูกเก็บเป็นคำตอบอ้างอิงได้ / คำตอบที่ได้ 👎 เก็บเฉพาะ "ความต้องการจริง" ที่ผู้ถามบอก
- คำตอบโหมดฐานความรู้ไม่ถูกเก็บซ้ำเป็นคำตอบ (กันคำตอบอ้างตัวเองวนไปเรื่อย ๆ) แต่ผลโหวตยังใช้สอนการอ่านความต้องการ
- หน้า **ข้อมูลการใช้งานจริง** แสดงความต้องการที่พบบ่อย คำที่ถามบ่อย อัตราที่ตอบตรง โปรไฟล์ และเคสทั้งหมด

## เริ่มใช้งาน

ต้องมี Node.js 20 ขึ้นไป

```bash
npm install
npm start                                  # http://127.0.0.1:3000 — โหมดฐานความรู้
ANTHROPIC_API_KEY=sk-ant-... npm start     # ให้ Claude ตอบ
```

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `ANTHROPIC_API_KEY` | – | มีค่า = ให้ Claude ตอบ (หรือ `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_PROFILE`) |
| `RABURD_LLM` | อัตโนมัติ | `off` บังคับโหมดฐานความรู้, `on` บังคับใช้ Claude (เช่นล็อกอินด้วย `ant auth login`) |
| `CLAUDE_MODEL` | `claude-opus-5-5` | โมเดลที่ใช้ตอบ |
| `CLAUDE_EFFORT` | `medium` | `low` / `medium` / `high` / `xhigh` / `max` |
| `ENABLE_WEB_SEARCH` | ปิด | `1` = ให้ Claude ค้นเว็บได้ (แสดงแหล่งอ้างอิงใต้คำตอบ) |
| `PORT` / `HOST` | `3000` / `127.0.0.1` | ตั้ง `HOST=0.0.0.0` เมื่อ deploy |
| `RABURD_DATA_DIR` | `.data/` | ที่เก็บบันทึกการใช้งาน (`usage.jsonl`) และเคสที่นำเข้า |
| `RATE_LIMIT` | `30` | จำนวนคำถามต่อ IP ต่อ 10 นาที (`0` = ไม่จำกัด) |
| `INSIGHTS_SHOW_QUESTIONS` | ปิด | `1` = แสดงคำถามล่าสุดรายข้อในหน้าข้อมูล (ปิดไว้เมื่อเปิดให้คนอื่นใช้) |
| `RABURD_HIDE_PRIVATE` | ปิด | `1` = ไม่แสดงเนื้อหาเคสส่วนตัวที่นำเข้า ทาง API |

การเรียก Claude ใช้ streaming, adaptive thinking (ค่าเริ่มต้นของ Opus 5.5), cache system prompt และเปิด
**server-side fallback** (`fallbacks: "default"`) ไว้ — ถ้าระบบความปลอดภัยของโมเดลปฏิเสธ API จะลองโมเดลสำรองที่เหมาะสมให้เอง
ถ้าเรียก Claude ไม่สำเร็จ หน้าเว็บจะบอกสาเหตุและแสดงคำตอบจากฐานความรู้แทน

## เพิ่มประวัติการใช้ Claude ของคุณเอง

```bash
# claude.ai: Settings → Privacy → Export data → แตก zip
npm run import-history -- ~/Downloads/claude-export/conversations.json --dry-run
npm run import-history -- ~/Downloads/claude-export/conversations.json

# Claude Code
npm run import-history -- ~/.claude/projects/<โปรเจกต์>/
```

สคริปต์จับคู่ คำถาม → คำตอบสุดท้ายของเทิร์น, ลบอีเมล/API key/โทเค็น, เดาประเภทความต้องการ
แล้วเขียนลง `.data/knowledge/imported.json` (ส่วนตัว ไม่เข้า git) — รีสตาร์ตเซิร์ฟเวอร์เพื่อโหลด
ใส่ `--public` ถ้าต้องการให้ไปอยู่ใน `public/data/knowledge/` (จะถูกเผยแพร่ไปกับเว็บ ตรวจเนื้อหาก่อน)

## หน้าเว็บที่เปิดได้ทันที (ใน Claude)

```bash
npm run build:artifact      # → dist/raburd-artifact.html (ไฟล์เดียว รวม HTML/CSS/JS/ฐานความรู้)
```

ไฟล์นี้เผยแพร่เป็นหน้าเว็บใน Claude (Artifact) ได้ โดยประกาศความสามารถ
`{"sample": {}, "db": {"rules": [{"path": "usage", "read": "interact", "write": "interact"}]}}`
— Claude ตอบผ่านบัญชีของผู้เปิดหน้า (ไม่ต้องมี API key, ขออนุญาตครั้งแรกที่ถาม)
และคำถาม/ผลโหวตถูกเก็บใน collection `usage` ของหน้า ซึ่งอ่าน-เขียนได้เฉพาะเจ้าของและผู้มีสิทธิ์ Contributor ขึ้นไป
ถ้าผู้ชมไม่อนุญาตให้ใช้ Claude หน้าเว็บจะตอบจากฐานความรู้แทน

## Deploy แบบ static (เช่น GitHub Pages)

โฟลเดอร์ `public/` ใช้งานได้โดยไม่ต้องมีเซิร์ฟเวอร์: หน้าเว็บจะตรวจว่าไม่มี `api/` แล้วคำนวณการค้นเคสและอ่านความต้องการในเบราว์เซอร์
(ตอบจากฐานความรู้ ผลโหวตเก็บในเบราว์เซอร์ของผู้ใช้แต่ละคน) — ถ้าต้องการให้ Claude ตอบต้องรัน `server.js`
เพราะ API key ต้องอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น

## ความเป็นส่วนตัว

- repo นี้เป็น public: เคสใน `public/data/` สรุปจากประวัติการใช้งานจริงโดยตัดชื่อบุคคล อีเมล และ ID เซสชันออกแล้ว
- คำถามที่ถามในเว็บถูกบันทึกใน `.data/usage.jsonl` บนเครื่องที่รันเท่านั้น (อยู่ใน `.gitignore`)
- ข้อความทั้งหมดที่แสดงผลถูก escape ก่อน render Markdown และมี Content-Security-Policy จำกัดสคริปต์ให้มาจากเว็บเดียวกัน

## โครงสร้าง

```
server.js                    HTTP server: static + API (/api/ask แบบ SSE, /api/feedback, /api/insights …)
src/claude.js                เรียก Claude แบบ streaming (+ pause_turn, citations, ข้อความ error ภาษาไทย)
src/store.js                 บันทึกการใช้งานจริง → เคสที่เรียนรู้
src/knowledge.js             โหลดประเภทความต้องการ โปรไฟล์ และเคส
public/engine.js             แกนกลาง (ใช้ทั้งเซิร์ฟเวอร์และเบราว์เซอร์): ตัดคำ ค้นเคส อ่านความต้องการ สร้าง prompt
public/app.js, markdown.js   หน้าเว็บ
public/data/                 ฐานความรู้จากการใช้งานจริง
scripts/import-history.js    นำเข้าประวัติ claude.ai / Claude Code
scripts/build-artifact.js    รวมเป็นไฟล์เดียวสำหรับหน้าเว็บใน Claude
test/                        npm test
```

## ทดสอบ

```bash
npm test
```

ครอบคลุม: การจับคู่คำถามที่ถามซ้ำคนละแบบ, การอ่านความต้องการ, การไม่เดาเมื่อไม่มีเคสที่ใกล้พอ, การเรียนรู้จากผลโหวต,
รูปแบบคำขอที่ส่งไป Claude (ผ่าน SDK จริงกับ fetch จำลอง), การ fallback เมื่อ Claude ล้มเหลว, การนำเข้าประวัติ,
การกัน path traversal / prompt injection / XSS และความสอดคล้องของข้อมูล
